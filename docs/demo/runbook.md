# 시연 운영

## A. 배포 URL (Vercel, 한 기기 체험 모드)
1. `/` → "한 화면에서 전체 체험" (노트북 권장). 학생 휴대폰·키오스크·직원·모니터가 한 브라우저 안에서 연동.
2. 키오스크에서 두 브랜드 주문 → 번호표의 "이 기기에서 열기" → 학생 화면에 주문 연결.
3. 직원 화면에서 한 매장만 완료 → 모니터와 학생 화면이 바로 바뀜.
4. 다른 휴대폰으로 QR을 찍으면 "주문한 브라우저에서만 연결돼요" 안내가 나옴(정상). 기기 간 연동은 공용 저장소 승인 후.

## B. 노트북 서버 (본선 현장, 실제 여러 기기)
```bash
npm ci && npm run build
FLOWEAT_STORE=memory npx next start -H 0.0.0.0 -p 3000
```
- 노트북 핫스팟 또는 같은 Wi-Fi. 키오스크(태블릿)는 `http://<노트북 IP>:3000/kiosk?k=L2&s=<세션>` 으로 열어야 QR 주소가 휴대폰에서 열림.
- `/`에서 새 세션 → 휴대폰은 학생 화면 QR로 접속 → 키오스크 번호표 QR 스캔.
- 휴대폰 카메라 스캔은 http에서도 동작(기본 카메라 앱 → 브라우저). 앱 안 스캐너는 https 또는 localhost에서만 카메라 사용 가능.

## 장애 대응
| 증상 | 대응 |
|---|---|
| 휴대폰에서 QR 주소가 안 열림 | 키오스크를 localhost로 열었는지 확인 → IP 주소로 다시 열기 |
| 완료가 휴대폰에 늦게 옴 | 네트워크 끊김 → 자동 재연결(최대 8초). 화면을 새로고침해도 상태는 서버에서 다시 받음 |
| 영상 직접 분석이 안 됨 | "기록된 분석 재생"으로 전환(같은 모델의 사전 추론 결과) |
| 주문이 섞임 | `/`에서 새 세션 또는 주문 초기화 |
| 서버 재시작 | 메모리 저장소라 주문이 사라짐 → 새로 주문 |

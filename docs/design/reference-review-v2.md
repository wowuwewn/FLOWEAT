# 디자인 검수 v2 — 추가 레퍼런스 반영과 개선 방향

작성 2026-11-24 (Claude Code). 기존 결과물(v1, `design-system.md`)의 완성도가 기대에 못 미친다는 피드백에 따라, 추가 레퍼런스를 실제로 열어 보고 v1을 다시 검수했다.

## 2. 레퍼런스에서 확인한 사실과 옮길 원칙

| 레퍼런스 | 확인한 내용 | FLOWEAT에 옮길 것 |
|---|---|---|
| Mappedin | 흰 벽을 살짝 세운 **2.5D 기울인 평면**, 밝은 회색 바닥, 원형 아이콘 배지 + 짧은 라벨("Kitchen", "Lounge"), 선택 구역은 옅은 파랑, 왼쪽 떠 있는 검색·카테고리 패널, 키오스크용 어두운 테마. 색은 대부분 흰색·회색이고 강조색은 소수. "Different views for different needs"(레이어) | 지도를 장식 도식이 아니라 **공간**으로 그림. 라벨 체계(배지+짧은 이름), 레이어 전환, 선택 하이라이트, 강조색 절제 |
| Google 인기 시간대 | 평소 혼잡 그래프 위에 **실시간 값을 겹쳐** 보여 줌, 대기시간은 "서비스를 받기까지" 기준. 붐비는 지역은 **총 인원을 표시하지 않고 평소 대비**로만 강조, 데이터가 부족하면 **게시하지 않음**, 구역 안의 정확한 위치는 숨김 | 작은 추세선 대신 **"평소 vs 지금" 시간대 막대 차트**, "평소보다 붐벼요" 같은 상대 표현, 정보 부족 시 숨김 유지 |
| Apple Live Activities | 시작과 끝이 있는 작업에만 사용. 한눈에 볼 핵심만, 큰 글자·중간 이상 굵기, **새 내용이 있을 때만 업데이트**, **꼭 필요한 순간에만 알림**, 탭하면 관련 화면으로 바로 이동, 민감한 정보 금지 | Order Island를 축소(번호+상태)와 확장(완료) 두 형태로 정리, 알림은 '준비 완료' 한 번만 |
| Apple Notifications | 짧은 제목, 완전한 문장, 같은 일로 여러 번 알리지 않기, 앱 이름 넣지 않기 | 알림 문구를 "비비고고 129번이 준비됐어요"로 정리 |
| Apple Wallet 주문 | 주문 상태, 예상 도착, 문제 여부, 상세와 판매자 링크를 **주문 단위**로 관리 | 주문을 '패스'로: 매장 → 번호 → 상태 → 예상 → 상세 순서, 주문별로 따로 |
| 토스 ListRow / BottomSheet | 행은 left(아이콘)–contents(텍스트)–right(부가 정보·행동) 세 영역, 들여쓴 구분선, 상하 여백 4단계. 바텀시트는 제목 + 부제목 + CTA, 페이지를 떠나지 않고 상세 표시 | 모든 목록을 같은 행 문법으로 통일, 지도 위 바텀시트로 상세 표시 |
| Toast KDS | 티켓이 **들어온 순서대로** 표시, 'All Day'(진행 중 품목 합계), 준비 스테이션 분배, 색으로 구분한 옵션, 인터넷이 끊겨도 매장 내 주문은 동작 | 직원 화면을 티켓 열(column) 구조로, 오래된 티켓 색 경고, 품목 합계 사이드바 |
| Supervision | 다각형 구역마다 고정 색을 쓰고 구역 안 인원을 셈, 기준점(anchor)으로 구역 진입 판정 | 운영 화면에서 구역마다 색과 **구역 중심에 인원 라벨**, 기준점 표시 유지 |
| DKU 웹진 사진 | 외관: 붉은 벽돌, **밝은 청색 "1947 COMMONS" 글자**, 유리 정면. 내부: **흰색 스탠딩 키오스크가 밝은 벽을 따라 줄지어** 있음, 원목 기둥, 흰 선형 조명, 긴 흰 테이블 | 브랜드 청색을 실제 간판 청색에 맞춤, 지도 재질(벽돌 정면, 원목 기둥, 흰 키오스크). 사진 속 마스코트와 사람은 쓰지 않음 |

Uber는 페이지에 실제 앱 화면이 없어, "지도 + 예상시간 + 상태 변화" 패턴은 일반적인 서비스 경험을 바탕으로 적용한다. 확인한 사실로 주장하지 않는다.

## 3. 최신 사용자 확인 사항 (2026-11-24)

정문에서 안쪽을 보는 기준:
- 왼쪽 키오스크 3대의 이용자는 오른쪽을 본다 → 화면은 왼쪽(바깥)을 향하고, 줄은 이용자 뒤인 왼쪽으로 생긴다.
- 오른쪽 키오스크 3대의 이용자는 왼쪽을 본다 → 화면은 오른쪽(바깥)을 향하고, 줄은 오른쪽으로 생긴다.
- 중앙 이동 공간은 v1 지도보다 넓다.
- 정확한 거리, 전체 평면도, 카메라 위치는 미확정이다.

v1 지도의 방향(화면이 바깥을 향함, 줄이 바깥으로)은 이 내용과 맞고, **중앙 통로 폭만 틀렸다.**

## 5. 개선 방향 v2 — "Commons Floor"

**한 줄 정의: 지도가 곧 앱이다.** 홈을 카드 목록에서 "지도 + 바텀시트" 구조로 바꾸고, 확인된 공간은 또렷하게, 확인 안 된 공간은 흐린 안개로 그린다.

### 5.1 지도 (최우선)
- **2.5D 정문 시점 지도**: 바닥은 밝은 회색 타일, 정면은 벽돌, 기둥은 원목, 키오스크는 흰 입체 기기이고 화면 방향을 표시. 기울기는 고정 약 35°에 회전은 막아 "정문에서 보는 방향"을 유지.
- **확인된 영역만 또렷하게**: 정문, 좌우 키오스크 3대씩, 넓은 중앙 통로까지만 실선과 재질로 그림. 그 너머 식사 공간은 **"아직 확인 전인 공간"이라는 흐린 안개 면**으로 처리하고, 좌석·수령대·모니터의 위치는 만들지 않음. 범례에 "개념 배치, 실측 아님".
- **줄 표현**: 이용자 뒤로 사람 토큰이 실제 간격으로 늘어섬. 혼잡 색은 토큰에만 쓰고, 예상시간은 지도 라벨(배지 + 큰 숫자)로 표시.
- **상호작용**: 두 손가락 확대·이동, 두 번 탭해 확대, "정문 시점으로" 복귀 버튼, 키오스크를 탭하면 선택 하이라이트와 함께 시트의 해당 행이 동기화됨.
- **레이어 전환**: [주문 줄] [자리] [수령] 세그먼트. 자리와 수령은 위치가 미확인이라 지도 대신 시트 목록이 중심이 되고, 지도에는 "위치 확인 전" 안내만 표시.

### 5.2 학생 앱 구조
```
┌──────────────────────────┐
│ FLOWEAT ◦   시연 12:14    │ ← 지도 위에 떠 있는 상단 바
│                          │
│    2.5D 정문 시점 지도     │ ← 화면 위쪽 약 55%, 확대·이동 가능
│  [3–5분]▣      ▣[2–4분]  │
│        정문 ▔▔▔           │
├──── 바텀시트 (3단 스냅) ─────┤
│ 지금 주문까지 2–4분        │ ← 헤드라인 1줄
│ [주문 줄][자리][수령]      │ ← 레이어 세그먼트
│ ▣ 오른쪽 가운데   7명  2–4분│ ← ListRow (left/contents/right)
│ ...                      │
│ 시간대별 혼잡 ▁▃▆█▆▃ 평소 vs 지금 │
└──────────────────────────┘
```
- 진행 중인 주문이 있으면 시트 맨 위가 주문 패스로 바뀜 (지도와 상태 결합).
- 메뉴 탭: 토스 ListRow 문법, 왼쪽에 조리 유형 아이콘(직접 제작), 오른쪽에 준비시간. 검색창 고정.
- 고지 문구: 화면마다 반복하지 않고 출처 칩 1개 + 데이터 안내 시트 1곳으로 모음.

### 5.3 주문 패스와 알림
- 주문 1건 = 패스 1장: 매장명 띠 → 큰 번호 → 상태(접수 → 완료, 실제 이벤트만) → 예상 범위 → 품목·키오스크·주문 시각 → 수령 안내.
- Order Island는 두 형태: 축소(번호와 짧은 상태)와 확장(완료 순간에 한 번). "준비 완료" 알림은 주문당 1회.

### 5.4 키오스크·직원·모니터·운영
- **키오스크**: 사진 속 흰 스탠딩 키오스크의 세로 화면 비율 유지, 메뉴 타일에 조리 유형 아이콘과 "준비 n–m분" 칩, 장바구니 하단 고정.
- **직원 (Toast KDS 참고)**: 티켓을 가로 열로 배치하고 들어온 순서대로 정렬. 티켓 머리 색은 경과시간 기준(예측 p50 넘으면 주황, p80 넘으면 빨강). 오른쪽에 'All Day' 품목 합계, 아래에 최근 완료 리콜 바.
- **모니터**: 현재 구조 유지, 간판 청색 계열로 맞춤.
- **운영 (Supervision 참고)**: 구역별 고정 색 채움, 구역 중심 인원 라벨("대기 2", "이용 중 14초"), 추적 꼬리선.

## 6. 진행 순서 (제안)
1. 2.5D 지도 엔진(SVG 기반, 확대·이동·선택) + 레이아웃 데이터 갱신(넓은 통로, 이용자 방향)
2. 홈을 지도 + 3단 바텀시트로 재구성, 레이어 전환, 시간대 차트
3. 주문 패스, Order Island 두 형태, 알림 문구
4. 직원 KDS 재구성, 운영 화면 구역 라벨
5. 로고·색 확정, 키오스크·모니터 정리, 접근성·E2E 회귀 테스트, 스크린샷 비교 검수

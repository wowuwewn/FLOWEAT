## 관찰한 것 → 적용한 것
**실내 지도 (Mappedin, Apple 지도)**
- 바닥은 흰색, 바깥은 아주 옅은 회색. 공간은 얇은 회색 선과 아주 옅은 면 색으로만 구분 → 우리 지도도 흰 홀 + 옅은 모래색(노란 매장 구역)·옅은 하늘색(파란 구역).
- 매장 이름은 상자 없이 글자만, 흰 테두리(halo)로 읽히게. 상자(pill)는 “데이터”(시간·번호)에만 → 예상 대기 칩만 상자를 씀.
- 2D 길찾기 화면이 가장 읽기 쉬움. 3D는 자산(모델)이 정확할 때만 고급스러움(경기장·캠퍼스). 우리 자료는 축척 없는 안내도라 3D가 오히려 “없는 정확도”를 만듦.
- 보조 조작(확대·층 선택)은 오른쪽 아래 작은 흰 버튼 묶음.

**하단 시트 (Apple 지도)**
- 시트 맨 위 = 모드 선택, 그 아래 = 한 줄 요약(큰 숫자 하나 + 작은 보조 정보), 그 아래 = 목록. 설명문 없음.
- 큰 숫자도 22pt 안팎. 굵기·회색 단계로 위계를 만들지 글자를 키우지 않음.

**한국어 타이포그래피 (토스)**
- 제목 22px 700, 본문 행 16–17px 500, 보조 13–14px 회색(#8b95a1 계열). 자간은 약간 좁게(−0.01~−0.025em), 숫자는 굵게 + 단위는 한 단계 작게(“15,000원”).
- 목록 행은 테두리·카드 없이 여백과 정렬로만 구분. 키–값 행은 왼쪽 회색 라벨, 오른쪽 진한 값.
- 화면당 강조색은 하나(파란 버튼·숫자). 배지·안내문이 거의 없음.

## 비교 렌더링으로 정한 것
1. **지도: 2D 평면 선택.** 같은 데이터로 현재 2.5D, 2D 평면, three.js 3D(그림자·재질·사람 모형)를 렌더링해 휴대폰 크기에서 비교(`docs/design/compare/v3/map-2d-25d-3d.png`).
   - 2.5D: 원근 때문에 안쪽 매장이 납작해지고 격자·사다리꼴이 산만함.
   - 3D: 실내 지도 느낌은 나지만 줄 모형이 화면을 덮고 라벨이 겹침. 테이블 배치를 지어내야 함. WebGL 부담.
   - 2D: 줄 길이·예상 시간이 가장 잘 읽히고, 확인 안 된 곳은 “그리지 않는” 것으로 정직하게 표현 가능.
2. **대기열 시트: 공간 배치 격자 선택.** 애플형 묶음 목록 / 토스형 평면 목록 / 정문 기준 2×3 격자를 렌더링해 비교(`docs/design/compare/v3/sheet-abc.png`). 격자는 6대가 한 화면에 다 보이고 지도와 같은 배치라 따로 설명이 필요 없음.

## 원칙
- 화면마다 큰 숫자는 하나. 나머지는 13–18px.
- 상자는 의미가 있을 때만(데이터 칩, 공간 격자, 주문권). 카드 남발 금지.
- 설명 대신 상태: “1–3분”, “빈 테이블 14”, “준비 완료”. 조사 과정·면책 문구는 심사용 데이터 안내(`/data`)로.
- 확인 안 된 위치는 지도에서 그리지 않거나 그 항목에만 “미확인”.

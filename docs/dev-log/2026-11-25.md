## 발견하고 고친 문제
- 가운데 줄 주문 판정 0% → 발이 키오스크에 가려 기준점이 구역 밖. 머리 기준점으로 바꿔 해결(그래도 정면 카메라는 사람 겹침으로 24%).
- 다음 사람이 서면 이전 사람의 트랙 ID를 가져감(ID 도용) → 추적 중 트랙 우선 매칭.
- 교대가 1.5초 안에 일어나면 두 사람의 이용 기록이 합쳐짐 → 주문자 ID가 바뀌면 기록 분리. 이용 시간 오차 97초 → 7.7초(비스듬한 카메라).
- "빈 테이블 0/8"은 영상에 실제로 비워진 테이블이 없어서였음 → 라벨 재정의, 단위 테스트, 촬영 장면 B4 추가.
- 지도 첫 시안: 전체 폭 맞춤으로 납작한 띠 모양, 45°에서 라벨 겹침 → 화면 맞춤 범위·줄 간격·기울기 재조정.
- 지도가 모바일에서 페이지 스크롤을 막음(touch-action:none) → 확대 전에는 세로 스와이프 허용, +/− 버튼 추가, UX 테스트로 고정.
- 개발 서버의 오래된 서버 번들로 하이드레이션 경고 → 재시작 후 사라짐(프로덕션 빌드 정상).

## 실제 배포 검수 후 수정 (P0–P3)
배포 주소에서 직접 검수(`docs/qa/live-audit-2026-11-25.md`) → 승인 → 수정.
- **P0 휴대폰 전체 체험**: `/demo/split`을 화면 크기별로 재구성. 휴대폰은 4개 화면을 탭으로 전환하고 단계 안내·자동 전환(번호표 연결 → 학생 앱)·새 소식 점·완료 알림을 띄움. 태블릿은 학생 휴대폰 고정 + 나머지 전환, 노트북(높이 820 미만)은 직원/모니터 전환, 데스크톱은 4개 동시. iframe은 배치가 바뀌어도 다시 만들지 않아 주문 상태가 유지됨.
- 직원 화면에 시연용 **모든 매장** 보기 추가(분할 체험 기본값). 매장을 고른 뒤 머리말이 잘려 보이던 스크롤 위치 문제 해결.
- 호출 모니터: 컨테이너 크기 단위로 글자·칸을 맞춰 1280×720 분할 칸에서도 10개 매장이 모두 보임. 실제 체험 번호(진한 흰색·완료 직후 노란색)와 시뮬레이션 번호(흐리고 작게)를 범례로 구분.
- **지도**: 휴대폰 지도를 실제 남은 공간 크기로 그려 확대 버튼이 시트에 가려지지 않음. 터치 더블탭 확대 직접 구현(모바일 브라우저의 dblclick 미발생 대비). PC는 6개 줄이 모두 들어오게 화면 맞춤 범위를 넓히고 남는 높이는 미확인 공간 쪽으로. 자리·수령 탭 안내는 지도 위 HTML 칩으로 옮겨 말풍선과 겹치지 않음(“아래 목록” → “목록으로”).
- **AI 실행 방식**: WebGPU를 무조건 쓰지 않음. WASM을 먼저 만들고, 하드웨어 GPU일 때만 WebGPU를 만들어 같은 입력으로 측정해 20% 이상 빠를 때만 선택. 소프트웨어 GPU(SwiftShader 등)는 제외, 결과는 기기별 14일 캐시, 실행 중 오류·급격한 저하 시 WASM으로 전환. 화면에 선택 이유 표시. (`?ep=wasm|webgpu|auto`)
- **AI 분석 화면**: 캔버스 라벨 충돌 회피(구역 집계 우선, 사람 라벨은 빈자리에만), 휴대폰에서 라벨 크기 보정, 왼쪽 카드 늘어남과 빈 공간 제거, 상태 문구 줄 분리.
- **메뉴·키오스크**: 브랜드 표식(로고 아님, 중립 글자 타일), 빨리 나오는 순 정렬, 시작 가격·대표 메뉴, 준비시간 막대. 키오스크는 매장 타일 시작 화면, 단계 표시, 메뉴 유형 칩, 매장별 결제 요약, 번호표 카드의 연결 버튼.
- **완성도**: 한국어 404, 링크 미리보기(OG·트위터 이미지, 직접 만든 지도 캡처), apple-touch-icon·PNG/마스커블 아이콘·매니페스트, 진입 화면 배지 줄바꿈, 프레임 안 “체험 홈” 링크 숨김.

## 독립 검수 반영 (기준 커밋 5c7a281)
별도 Claude Code 세션의 독립 검수 결과를 받아 수정.

### 주문·사용성
- 직원 ‘되돌리기’ 시 학생 화면의 준비 완료 배너·탭 제목 깜빡임을 즉시 철회하고 “매장이 완료를 취소했어요” 안내. 재완료 시 배너는 주문당 하나(중복 없음), 모니터는 다시 강조.
- **롱폴링 연결 고갈**: 탭·iframe마다 20초 롱폴링을 열어 HTTP/1.1 동시 연결 6개를 채움 → 브라우저당 한 탭만 롱폴링(Web Locks로 선출)하고 BroadcastChannel로 나눔. 측정(같은 스크립트, 노트북 서버): 이전 빌드는 4번째 탭 열기 17초, 5·6번째 30초 초과, 직원 완료 처리 안 됨 → 현재 탭 6개 0.13–0.26초, 직원 완료 93ms, 학생 반영 0.6초.
- 기본 시각은 점심 피크 반복, 실제 시각 연동은 선택. 한 기기 체험의 “다른 휴대폰으로 QR 스캔 불가”를 체험 홈과 번호표에 미리 안내.

### 보안 (노트북 서버 모드)
- 세션 코드만으로 직원 완료·세션 초기화가 가능했음 → 학생(QR 토큰)·키오스크·직원(세션별 직원 키)·운영자(운영자 키) 구분. 공개 피드는 품목을 숨김.
- `next start`가 클라이언트가 보낸 X-Forwarded-For를 그대로 통과시키는 것을 확인 → 헤더 기반 요청 제한 우회 가능 → 클라이언트·전체·세션 3중 버킷.
- 단위·E2E: 다른 세션 키 거부, 동시 완료 8건 중 1건만 반영, 되돌린 뒤 재완료, 중복 요청 무시.

# WebKit 검증 (2026-11-26)

## 무엇으로 검증했나
- **Playwright WebKit 26.6 (Linux 빌드)**: Safari와 같은 렌더링·JS 엔진(WebKit/JavaScriptCore). `playwright.config.ts`에 `webkit` 프로젝트를 추가해 **전체 E2E를 Chromium과 똑같이** 돌린다(`npm run e2e`).
- **실제 iPhone Safari는 검증하지 않았다.** 이 개발 환경에는 아이폰·macOS·iOS 시뮬레이터가 없다. 아래 "에뮬레이션으로 확인 못 하는 것"은 실기기에서 따로 확인해야 한다.

## 결과
- E2E 92/92 통과 (Chromium 46 + WebKit 46). 엔진 집중 검사 `e2e/engines.spec.ts` 7개 포함.
- 7개 해상도 × 17개 화면 스윕: WebKit 0건, Chromium 0건 (아래 수정 후).
- WebKit 기능 탐지(iPhone 13 에뮬레이션): WebGL·WebGL2 있음, WebGPU 없음, `Notification` 없음(iOS 탭과 같음), `getUserMedia` API는 있으나 카메라 장치 없음, H.264 재생 가능, WASM 있음.

## 검증 중 찾아서 고친 것
1. **멱등 키가 세션·주문을 넘어 공유됨** (`memory-repo.ts`): 한 세션에서 쓴 키가 다른 세션·주문의 호출을 막을 수 있었다. 키를 (세션, 주문)으로 한정, 단위 테스트 추가. WebKit 프로젝트가 같은 서버에서 두 번째로 돌면서 드러남.
2. **모니터 하이드레이션 오류** (React #418): 새 공용 화면의 페이지가 시계로 정해져 서버·브라우저가 어긋날 수 있었다. 마운트 후에 페이지 결정.
3. **QR 카메라 안내**: 카메라가 없을 때도 ‘권한이 없어요’라고 했다. `NotAllowedError`와 장치 없음 구분.
4. **`vh` → `svh`**: iOS Safari에서 `vh`는 툴바가 숨었을 때 기준이라 지도·시트가 화면보다 커질 수 있다.

## 에뮬레이션으로 확인 못 하는 것 (실제 iPhone에서 확인 필요)
- **진짜 멀티터치 핀치**: 합성 포인터 이벤트로 로직만 검증. iOS의 `gesturestart`·페이지 확대와의 충돌은 실기기 필요.
- **카메라**: Linux WebKit에는 카메라가 없다. iOS 권한 팝업, 후면 카메라, `playsinline` 미리보기, jsQR 인식률은 미검증.
- **실제 GPU WebGL 성능·발열**: 소프트웨어 렌더러로만 확인. 오래된 iPhone에서 360° 프레임 속도 미검증.
- **iOS 툴바·홈 인디케이터**: 주소창이 접히고 펴질 때의 높이 변화와 실제 안전 영역 값(34px 등)은 에뮬레이션되지 않는다.
- **알림**: 홈 화면에 추가한 웹앱(iOS 16.4+)에서의 푸시 알림은 미검증(현재 앱은 화면 안 배너가 기본).
- **영상**: iOS 저전력 모드의 자동 재생 차단, 실제 기기의 WASM 스레드(교차 출처 격리) 동작.

## 실기기 체크리스트 (팀원용)
1. Safari로 배포 주소 `/app` 열기 → 지도 두 손가락 확대·축소, 페이지가 확대되지 않는지.
2. ‘360° 둘러보기’ → 드래그 회전, 위치 탭, 닫기. 버벅임 정도 기록.
3. `/app/scan` → 카메라 권한 허용·거부 각각, 영수증 QR 인식.
4. 키오스크 → 영수증 → 학생 앱 연결 → 호출기 호출 → 준비 완료 배너, 소리·진동 없음 확인.
5. 주소창이 접힐 때·펴질 때 하단 탭과 시트가 홈 인디케이터에 가리지 않는지.
6. `/ops` 기록 재생 영상 재생, ‘이 브라우저에서 실시간 추론’ 시작 여부와 ms/프레임.
